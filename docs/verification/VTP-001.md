# VTP-001: verification plan

## Purpose

Show, with repeatable commands, that the checks described in
`docs/architecture.md` do what the design says, and record which parts are not
yet verified. Results come from running the commands, not from this document.

## Environment

WSL2, Ubuntu 24.04, no containers. Tools: GHDL, Rust (with the
`riscv32imac-unknown-none-elf` target and `llvm-tools`), Ubuntu GNAT with
`gprbuild`, GNATprove and the `riscv64-elf` GNAT from Alire, Renode, Kani for `make kani`, Python 3.11
or newer. `make check-tools` reports which are installed.

## The original five steps

| Step | Check | Command | State |
|---|---|---|---|
| 1 | Hardware module testbench (GHDL) | `make test-hdl` | implemented |
| 2 | Formal proof of BL1 | `make prove` | implemented |
| 3a | BL2 unit and integration tests, host | `make test-bl2` | implemented |
| 3b | Bounded model checking of BL2's parser, pipeline, state machine and NV codec | `make kani` | implemented |
| 4 | Fuzzing and static analysis of the C update parser | `make fuzz-app`, `make test-app`, `make lint-app` | implemented; MISRA findings not triaged |
| 5 | Co-simulation of the RoT with the emulator | `make cosim-all`, `make chain-all ROT=ghdl` | implemented |

## Additional checks

| Check | Command |
|---|---|
| Shared formats are consistent and match the code | `make spec-check` |
| Test vectors reproduce byte for byte | `make vectors-check` |
| Host tool: header, signing, verification, vectors | `make test-cli` |
| The RoT through the bridge protocol, without the emulator | `make bridge-test` |
| BL1 parser, SHA-256 and Ed25519 on the host | `make test-bl1`, `make test-sha256`, `make test-ed25519` |
| BL1 built for RV32 gives the host build's verdicts | `make renode-bl1` |
| BL2 scenarios on the emulator | `make renode-all` |
| The whole chain, with damage at every link | `make chain-all` |
| The documents match the repository | `make docs-check` |

## Running everything

```bash
make verify-quick                     # no emulator
make verify 2>&1 | tee build/verify.log
```

`make verify` runs the quick set, builds BL1 for RV32, and then every emulator
scenario with the scripted root of trust and with the VHDL one. It takes a while,
mainly for the proofs and the emulator runs.

## Pass criteria

- Every command exits successfully.
- `make prove` reports no unproved or timed-out check. This is part of the claim
  made in ADR-005: the shipped BL1 is compiled with run-time checks off.
- Each Renode scenario prints `[ok] boot behaved as expected`; the chain run ends
  with `[ok] the whole chain behaved as expected`.

## Recording a run

Keep the log of the last full run (`build/verify.log`) with the commit it was
made from. The documents make claims about what the commands show; the log is the
evidence that they did, on that commit.

## Not verified

REQ-004's model-checking half, REQ-005 entirely, power loss in the emulator,
anything on real hardware, timing and performance, and Monocypher's internals.
See `docs/compliance/traceability.md` and ADR-005.
